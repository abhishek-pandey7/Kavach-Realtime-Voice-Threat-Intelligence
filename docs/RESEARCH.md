# Research notes

This file records the research behind Kavach's design: what each paper found, and what we changed because of it. Figures are as reported by the authors. Where we only read an abstract or summary, that is noted.

Last updated: October 11, 2026.

## 1. Real-time scam detection with LLMs

### 1.1 Shen et al., "It Warned Me Just at the Right Moment": Exploring LLM-based Real-time Detection of Phone Scams (2025)
[arXiv:2502.03964](https://arxiv.org/abs/2502.03964) · Zitong Shen, Sineng Yan, Youqian Zhang, Xiapu Luo, Grace Ngai, Eugene Yujun Fu (Hong Kong PolyU) · preprint

**What they did.** An LLM reads a call turn by turn and labels each turn FRAUD or SAFE (the "RT" setting). A variant adds an UNCERTAIN label so the model can defer. They compare against retrospective analysis of the whole call. Data: real scam/normal calls from public videos (transcribed) and synthetic calls, both in Chinese.

**Findings.**
- Real-time recall was 0.98 to 1.00 across models on both datasets.
- Real-time precision on synthetic data was only about 0.70 to 0.77, compared with 0.95 to 1.00 for retrospective analysis. Judging an utterance with little context causes false positives on isolated words such as "payment".
- Adding UNCERTAIN raised precision (e.g. one model from 0.70 to 0.85) at a small recall cost (0.90 to 0.98) and later alerts.
- Users see early alerts as "jumping to conclusions" and late ones as "too late to be useful". Timing is a design problem, not just an accuracy problem.

**What we changed.**
- Evon sees the **whole call so far** (rolling window), not a single utterance.
- Evon's output includes an explicit `UNCERTAIN` verdict. Kavach never speaks on UNCERTAIN.
- We report three numbers together: precision, recall and time-to-warning.
- The escalation ladder (watch, soft warning, hard warning) exists to manage the timing trade-off.

### 1.2 Shen et al., Combating Phone Scams with LLM-based Detection: Where Do We Stand? (AAAI 2025 student abstract)
[arXiv:2409.11643](https://arxiv.org/abs/2409.11643) · [AAAI](https://ojs.aaai.org/index.php/AAAI/article/view/35298)

**Findings (abstract level).** LLMs can detect scams from the scammer-victim conversation, but face biased datasets, relatively low recall and hallucinated reasoning.

**What we changed.**
- Evon must quote **evidence** (exact phrases from the transcript) for every red flag. Flags without a matching quote in the transcript are dropped. This is a simple hallucination guard.
- Hard negatives in the eval set guard against dataset bias (scam calls that are "obviously" different from normal calls).

### 1.3 Ma et al., TeleAntiFraud-28k: An Audio-Text Slow-Thinking Dataset for Telecom Fraud Detection (2025)
[arXiv:2503.24115](https://arxiv.org/abs/2503.24115) · China Mobile Internet · preprint

**What they did.** 28,511 Mandarin audio-text pairs. Real recordings were transcribed and re-voiced with TTS for privacy; more scripts were generated by LLM self-instruct and a multi-agent simulation (caller, callee, manager). Three tasks: scenario classification, fraud detection, fraud type. Reasoning traces were produced by a reasoning LLM before a JSON answer with confidence.

**Findings.**
- An ASR + reasoning-LLM pipeline (SenseVoice + DeepSeek-R1) scored about 82.7 average F1, close to the best fine-tuned audio model (83.0).
- Non-reasoning LLMs varied hugely on fraud detection (one scored 14.6 F1 against 79.3 for the reasoning model). Prompt and model choice matter a lot.
- Adding audio cues (tone, pauses) and reasoning-style training improved results. Rare fraud types stayed hard.

**What we changed.**
- Confidence that an **ASR + LLM** design (Prisma + Evon) is a sound architecture.
- Evon's output is **structured JSON** with scenario, verdict, scam type and confidence, mirroring their three-step format.
- Our eval set is built the same privacy-preserving way: scripts generated by LLM, voiced by TTS (Timbre), plus a few human-recorded staged calls.
- We balance the eval set across scam types so rare types are not ignored.
- Use Evon's thinking mode for the post-call debrief and eval labelling, where latency doesn't matter; keep it off for live verdicts. Compare both settings in the ablation.
- Future work: add prosodic cues (pace, pauses) from the audio.

### 1.4 TeleAntiFraud 2.0: A Refreshable, Profile-Grounded, and Audio-Based Benchmark for Telecom Fraud Detection (2026)
[arXiv:2609.18748](https://arxiv.org/abs/2609.18748) · read at summary level only

**Findings (summary).** Fraud F1 alone is misleading. Fraud calls must be compared against lawful calls from the same domain (near-domain negatives); they recommend balanced metrics and report shortcut separability, prediction collapse and class-prior effects.

**What we changed.**
- Our negatives are **near-domain**: real-style bank fraud alerts, delivery and KYC reminder calls, relatives asking for money.
- We report false alarm rate and balanced accuracy alongside recall, not F1 alone.
- We freeze the eval set once built and report against that fixed version.

## 2. Forecasting harm before it happens

### 2.1 Lee et al., Vishing-Tactics-Bench: Forecasting Exploitation Trajectories in Voice Phishing Calls (Findings of EMNLP 2026)
[arXiv:2609.07151](https://arxiv.org/abs/2609.07151) · abstract level

**What they did.** Reframe vishing defence from classifying a finished call to predicting, at every turn, whether the call will reach harm (information gathering or financial exploitation). They label 35,340 scammer utterances with a six-tactic taxonomy adapted from MITRE ATT&CK and evaluate with survival-style metrics under a tight false-alarm budget.

**What we changed.**
- Evon labels the **tactic stage** of each new utterance (hook, authority, threat, isolation, extraction).
- The risk scorer rewards **progression** through stages more than repeated hits on one stage. "Customs officer" alone is a watch; "customs officer" then "arrest" then "don't tell anyone" then "transfer for verification" is a hard warning.
- Thresholds are tuned to a fixed false-alarm budget (target at most 5% on hard negatives), then we report lead time under that budget.

### 2.2 Chang and Danescu-Niculescu-Mizil, Trouble on the Horizon: Forecasting the Derailment of Online Conversations as they Develop (EMNLP 2019)
[ACL Anthology D19-1481](https://aclanthology.org/D19-1481/)

**Findings.** Conversation-level models that read the dialogue as it unfolds can flag derailment before the harmful turn appears.

**What we changed.** Supports the forecasting framing above: we measure how many seconds *before* the payment request Kavach warns, not only whether it eventually flags the call.

## 3. Scam psychology

### 3.1 Stajano and Wilson, Understanding Scam Victims: Seven Principles for Systems Security (Communications of the ACM, 2011)
[Tech report UCAM-CL-TR-754](https://www.cl.cam.ac.uk/techreports/UCAM-CL-TR-754.html) · [USENIX Security 2010 invited talk](https://www.usenix.org/conference/usenixsecurity10/understanding-scam-victims-seven-principles-systems-security)

**Findings.** From studying real hustles, the authors identify seven recurring human vulnerabilities that scammers exploit: distraction, social compliance (deference to authority), herd behaviour, dishonesty, kindness, need and greed, and time pressure. They argue that systems must be designed around these rather than blaming users.

**What we changed.** Our red-flag categories map to these principles: `fake_authority`, `urgency`, `threat`, `secrecy` and `isolation`, `payment_demand`, `credential_request`, `remote_access`, `too_good_to_be_true`. The warnings we speak name the trick ("Police phone pe arrest nahi karti") rather than just saying "fraud", because naming the manipulation helps break it.

## 4. Privacy and robustness

### 4.1 Wang et al., One Size Fits All? A Modular Adaptive Sanitization Kit (MASK) for Customizable Privacy-Preserving Phone Scam Detection (2025)
[arXiv:2510.18493](https://arxiv.org/abs/2510.18493) · abstract level

**Findings.** Transcripts sent to an LLM contain personal data. MASK offers pluggable sanitisation, from keyword rules to neural methods, letting users trade privacy against accuracy.

**What we changed.** Before a transcript reaches Evon, a sanitiser masks digit sequences that look like OTPs, account, card, Aadhaar or phone numbers (replaced with tags like `<OTP>` or `<ACCOUNT_NO>`). The tag itself is a useful signal ("caller asked for an `<OTP>`"), so this costs little accuracy. Self-hosting Evon reduces exposure further.

### 4.2 Li et al., Talking Like a Phisher: LLM-Based Attacks on Voice Phishing Classifiers (EAI ICDF2C 2025)
[arXiv:2507.16291](https://arxiv.org/abs/2507.16291)

**Findings.** On a real Korean vishing dataset, LLM-rewritten scam transcripts cut ML classifier accuracy by up to about 31% while keeping the meaning. Rewrites take seconds and cost almost nothing.

**What we changed.**
- The eval set includes **paraphrased variants** of every scam script (rewritten by Evon to avoid our lexicon's words). We report recall on these separately.
- This is why the keyword layer is only a fast first pass and Evon makes the real decision.

## 5. Audio robustness

### 5.1 Iwamoto et al., How Bad Are Artifacts?: Analyzing the Impact of Speech Enhancement Errors on ASR (Interspeech 2022)
[arXiv:2201.06685](https://arxiv.org/abs/2201.06685)

**Findings.** After single-channel speech enhancement, processing artifacts, not leftover noise, are the main reason recognition gets worse. Mixing some of the original noisy signal back in ("observation adding") helps.

**What we changed.** No denoiser in front of Prisma. Prisma is trained on noisy telephone audio, so raw audio goes in. If we ever test enhancement, we include an observation-adding variant and compare.

### 5.2 Snyder, Chen and Povey, MUSAN: A Music, Speech, and Noise Corpus (2015)
[arXiv:1510.08484](https://arxiv.org/abs/1510.08484) · [OpenSLR 17](https://openslr.org/17/)

**Content.** About 109 hours of music, speech (12 languages) and noise (929 noise files, about 6 hours, including dial tones, DTMF, rain and wind), under Creative Commons and public-domain licences.

**What we changed.** MUSAN noises plus our own recordings of Indian household and street sounds (pressure cooker, traffic, TV, ceiling fan) are mixed into eval audio at 20, 10 and 5 dB SNR before 8 kHz G.711 coding.

## 6. Reasoning reliability

### 6.1 Wang et al., Self-Consistency Improves Chain of Thought Reasoning in Language Models (ICLR 2023)
[arXiv:2203.11171](https://arxiv.org/abs/2203.11171)

**Findings.** Sampling several reasoning paths and taking the majority answer beats a single greedy answer on reasoning benchmarks, with no extra training.

**What we changed.** Only in the borderline zone (risk between the soft and hard warning thresholds), we sample Evon 3 times in parallel and require a majority SCAM verdict before a hard warning. This costs GPU time, not Gnani credits, and only runs on the few utterances that need it.

## 7. Industry precedent

### 7.1 Google, Scam Detection on Android (2024 onwards)
[Google blog](https://blog.google/security/new-ai-powered-scam-detection-features/)

On-device models listen for "conversation patterns commonly associated with scams" (bank impersonation, urgent transfers, gift cards, PIN requests) and show a warning with an "End call" button. Processing is on the device; audio and transcripts are not stored. Launched for English calls on selected phones.

**What it tells us.** Live, in-call warnings are a validated idea. The gap Kavach fills is Indian languages, code-mixing, basic phones (via Guardian), and a spoken warning in a trusted voice rather than a screen pop-up an elderly user may miss.

## 8. Data resources

### 8.1 Indian Cyber Scam PhoneCall Hinglish Dataset (Hugging Face, community upload)
[Dataset page](https://huggingface.co/datasets/DatasetNewUser/Indian_Cyber_Scam_PhoneCall_Hinglish_Dataset) · Apache-2.0 · not peer reviewed

About 10,000 Hinglish lines labelled scam or not, with categories including digital arrest, police blackmail, bank KYC, Aadhaar, lottery and relative scams. Rows look templated and some category labels look wrong.

**How we might use it.** Only as an extra **text-level** sanity check for the keyword layer and Evon prompt, clearly labelled as a third-party, unvetted source. Not part of our headline results.

## 9. Supporting context

- **Familiar voices.** Children's brains respond much more strongly to their mother's voice than to unfamiliar voices, across reward, emotion and attention regions ([Abrams et al., PNAS 2016](https://pmc.ncbi.nlm.nih.gov/articles/PMC4896719)). This is about children, not adults, so we only cite it as a hint that a familiar voice gets attention. Whether a cloned family voice makes adults more likely to hang up is something we would need to test ourselves, and we will not claim it as proven.
- **Scale of the problem.** Government data cited by [Bloomberg (Oct 2025)](https://www.bloomberg.com/opinion/features/2025-10-12/digital-arrests-inside-india-s-scariest-scam-and-how-to-stop-it) puts digital arrest losses at ₹25.8 billion since 2022.

## Design decisions at a glance

| Decision | Driven by |
|---|---|
| Whole-call rolling context for Evon | 1.1 |
| Explicit UNCERTAIN verdict; never speak on it | 1.1 |
| Evidence quotes required for every red flag | 1.2 |
| ASR + reasoning LLM architecture, JSON verdict with confidence | 1.3 |
| Near-domain hard negatives; balanced metrics; frozen eval set | 1.4 |
| Tactic-stage tracking and progression-based risk | 2.1, 2.2 |
| Red-flag taxonomy and warnings that name the trick | 3.1 |
| Mask OTP/account/ID numbers before Evon | 4.1 |
| Paraphrased scam variants in eval | 4.2 |
| No denoiser before Prisma | 5.1 |
| MUSAN + Indian household noise at 20/10/5 dB, 8 kHz G.711 | 5.2 |
| Self-consistency vote before hard warnings | 6.1 |
| Spoken warning instead of only a screen alert | 7.1 |
